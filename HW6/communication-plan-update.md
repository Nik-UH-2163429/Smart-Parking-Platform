# HW6 – Updated Communication Plan

**Project:** Smart Parking Platform  
**Date:** October 15, 2026  
**Version:** 1.2

## 1. Purpose

The purpose of this Communication Plan is to establish how the Smart Parking Platform team will communicate project progress, risks, issues, responsibilities, and important decisions.

The original communication procedures remain in effect, with additional documentation practices introduced to support project management through GitHub.

## 2. Meeting Cadence

The existing meeting schedule has been maintained.

| Meeting | Participants | Frequency | Purpose |
|---|---|---|---|
| Team Check-In | Project Team | Weekly | Review completed work, current tasks, blockers, and upcoming responsibilities. |
| Development Review | Development Team | Weekly | Discuss technical progress, bugs, testing, and integration issues. |
| Project Progress Review | Project Team | Biweekly | Review milestones, schedule progress, risks, and project priorities. |
| Stakeholder Update | Project Team and Stakeholders | Weekly | Communicate project progress, completed work, risks, and next steps through the stakeholder update video. |

## 3. Communication Tools

### 3.1 GitHub

GitHub will continue serving as the central location for:

- Project documentation
- Version control
- Requirements and user stories
- Work Breakdown Structure
- Timeline and Gantt charts
- Product backlog and sprint plans
- Risk Register
- Cost and resource planning
- Communication records

Project changes will be documented through descriptive GitHub commits.

### 3.2 Project Tracking Transition

The product backlog and initial sprint planning were originally developed in Trello during HW3.

Following the expiration of the Trello trial, the team has transitioned to maintaining project tracking information through GitHub Markdown documents.

The original Trello screenshots will be retained as historical planning evidence.

Future backlog and sprint updates will be documented in the GitHub repository.

### 3.3 Weekly Stakeholder Video

A stakeholder video will be prepared each week to communicate important project updates.

Each video should address:

1. Work completed during the reporting period.
2. Updated project documents or deliverables.
3. Changes to project scope, schedule, cost, or risks.
4. Reasons for significant project decisions.
5. Outstanding issues or blockers.
6. Planned activities for the following week.

For HW6, the stakeholder update will specifically explain which existing documents were reviewed and revised, what was added, and why the changes were necessary.

## 4. Communication Responsibilities

| Role | Responsibility |
|---|---|
| Project Manager | Coordinate meetings, track project progress, review risks, and communicate stakeholder updates. |
| Development Team | Report technical progress, development issues, integration problems, and testing results. |
| QA / Testing Team | Communicate defects, testing results, and quality concerns. |
| Project Team | Keep assigned documentation current and report delays or blockers. |
| Stakeholders | Review project updates and provide feedback when necessary. |

These responsibilities retain the roles identified in the original communication plan and clarify reporting expectations.

## 5. Issue Escalation Procedures

The following escalation process is proposed for managing significant project concerns.

| Issue Type | Initial Action | Escalation |
|---|---|---|
| Technical Problem | Development Team investigates and documents the issue. | Project Manager reviews schedule or resource impacts. |
| Schedule Delay | Responsible team member reports the delay. | Project Manager evaluates milestone adjustments. |
| Budget Concern | Project Manager reviews the estimated cost impact. | Stakeholders are informed if the project budget may be affected. |
| Security Concern | Development Team documents and investigates the concern. | Project Manager coordinates urgent review and corrective actions. |
| Requirement Change | Team records the proposed modification. | Project Manager reviews effects on scope, schedule, and cost. |

Urgent issues should be communicated as soon as they are identified rather than waiting for the next scheduled meeting.

## 7. Documentation Maintenance

Project documentation should be reviewed when changes occur to:

- Functional or non-functional requirements.
- Development priorities.
- Sprint assignments.
- Project milestones.
- Budget and resource assumptions.
- Risk assessments.
- Team responsibilities.

Updated documents should include a revision date and an appropriate GitHub commit message.
